# Plan — Physics models: load reference, airspeed, free-body inertia, drag

These are physics laws that are wrong or inconsistent with each other. The tyre's load-sensitivity
reference follows the live mass, so the same load reaches the tyre laws three ways. The plane's
lift reads ground speed while its drag reads airspeed. The free bodies size their damper clamps off
a box proxy instead of the solver's inertia. Boat and plane drag is linear in speed. Smaller
items: an unguarded ABS/TC slip constant, two gravities, and sensing and counting written several
times. Findings: `reviews/A_vehicle_physics.md` #2, #6, #8, #13, #14, #15, #16.

Written 2026-11-05. Status: **not started.**
Serves: every vehicle family responding to load, wind and speed the way its sourced law says
(`docs/handling.md`, `docs/flight.md`, `docs/boat.md`).
State: done — nothing; next — phase 1; open findings — none.

## Phase 1 — Guards and one-homes (effort: medium; mode: accept-edits)

  re-measure the ESC gates.
- Done when the suite is green.

## Phase 2 — Free-body damper clamps on the solver's tensor (effort: medium; mode: plan-mode-first)

- #8: boat, plane and drone read `1 / VehicleMath.inverse_moment(self, axis)` per tick, as the ESC
  does, replacing `VehicleMath.inertia_of`. The drone's payload path then needs no separate
  update.
- Log proxy vs tensor once per body before switching, so the change is measured, not assumed.
- Done when the user has flown and sailed each body with no new oscillation.

## Phase 3 — Plane lift on airspeed (effort: medium; mode: plan-mode-first)

- #6: the code's comment calls ground-velocity lift deliberate ("wind is here to be flown
  against"), so the user decides first.
- If yes: `v_fwd`, `aoa`, `sideslip` and the authority read `linear_velocity - wind`, like the
  drag. The stall speed becomes an airspeed, and a crosswind crabs the nose into the wind.
- Use the `vehicle-feel` skill. Done when the user has flown a take-off into a headwind and a
  crosswind.
